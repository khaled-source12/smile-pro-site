## التشغيل المحلي

```sh
npm run check:staging
```

يبني الأمر `dist` تجريبيًا ويولد ملف [gtm-staging-container.json](gtm-staging-container.json). تستخدم النسخة التجريبية `GTM-NFTVFBKS` فقط، ويقبل ملف الحاوية الآن `smile-pro-tracking-test.netlify.app` و`smileproegypt.com` و`www.smileproegypt.com`، ويرفض أي hostname آخر.

- `TRACKING_ENV=staging`: نسخة اختبار، noindex وCMS مغلق لحماية مستودع الإنتاج.
- `CONTEXT=deploy-preview` أو `branch-deploy`: نفس الحماية، حتى مع `ELEVENTY_ENV=production`. لا يعمل التتبع على نطاق Preview مختلف عن النطاق المعتمد.
- `PERF_DISABLE_TRACKING=1`: تعطيل GTM للقياس المحلي.
- البناء الإنتاجي المعتاد يستخدم الآن الحاوية الجديدة بعد موافقة 19 سبتمبر على اختبار النسخة في الموقع الحي. تظل الحاوية القديمة داخل التصدير المرجعي فقط لتسهيل التدقيق والرجوع.

`_headers` و`_redirects` موجودان في المخرجات، لأن Netlify Drop لا يقرأ إعدادات مستودع `netlify.toml`. الروابط النظيفة والأسماء والحقول الخاصة بالنماذج لم تتغير.

## تشخيص مشكلة الوصول بعد إعادة النشر

- أحدث Deploy ظاهر في Netlify كـPublished، والملفات في الجذر الصحيح، والنطاق الافتراضي مرتبط بالمشروع.
- DNS المحلي وGoogle Public DNS متفقان على `63.176.8.218` و`35.157.26.135`.
- اتصال TCP على المنفذ 443 بهذين العنوانين يتوقف بمهلة، **قبل** TLS أو أي استجابة HTTP؛ رابط الـDeploy المباشر يتعطل أيضًا عبر المسار المعتاد.
- `app.netlify.com` يعيد HTTP 200 من نفس الجهاز.
- فحص قراءة مؤقت باستخدام `curl --resolve` إلى `75.2.60.5` — عنوان [Netlify الرسمي](https://docs.netlify.com/manage/domains/configure-domains/configure-external-dns/) — أعاد HTTP 200 على `/ar/` مع نجاح التحقق من شهادة HTTPS. لم نستخدم `-k` ولم نغيّر DNS أو ملف hosts أو إعدادات الجهاز.
- HTML المسترجع هو صفحة Smile Pro العربية الصحيحة، يحتوي `GTM-NFTVFBKS` فقط، ولا يحتوي `GTM-PZRLPZN2`، ومعه noindex.
- `robots.txt` المسترجع يحتوي `Disallow: /`. تحويل المقال القديم يعيد 301 إلى المسار النظيف الصحيح.

بناءً على ذلك، المشكلة الحالية ليست غياب Deploy أو خطأ مسار البناء؛ هي مشكلة الوصول إلى مسار الشبكة الذي يختاره DNS. يوجد أيضًا [رد حديث من دعم Netlify عن مشاكل وصول مشابهة من مصر](https://answers.netlify.com/t/site-unreachable-from-egypt-dns-resolves-globally-err-connection-aborted/169734). نسبة السبب إلى مزود إنترنت بعينه تظل استنتاجًا، لا قياسًا مؤكدًا لدينا.

لإكمال Preview من المتصفح نحتاج شبكة تستطيع الوصول إلى النطاق، أو إعداد نطاق فرعي تجريبي بموافقة المستخدم وإعداد DNS/TLS مناسب. لا نغيّر DNS الإنتاج أو نشتري نطاقًا أو نشغّل VPN أو نعدّل إعدادات الشبكة تلقائيًا.
